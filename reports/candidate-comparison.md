## Source inspection and separation of claims

All linked upstream paths above were fetched from their **literal Index `review_ref`**, not mutable main; their relevant code and documentation were inspected. The Index record itself owns the VSM classification; a retrieval snippet cannot prove downstream performance or universal architecture suitability.

The pre-registered D04 query surfaced an OpenHarness S4 package-management mechanism; it was excluded from this implementation comparison because it is about **installing a domain harness capability**, not repairing a dependency within one Python workspace. The D07 negative control returned 15 hits, and the trivial post hoc literal-term guard cannot erase those false positives. [Full results](../receipts/discovery/hit-index.json) remain visible.

## Design alternatives carried into the decision gate

- **No adaptation:** identical minimal agent, tools and scripted double, self-selected tests only. Necessary comparison baseline.
- **Fresh observed post-write test gate:** independent runner verifies tests *after* the most recent edit and refuses verified completion without a fresh success. Prompt the same model with a failing receipt while budget remains; never fabricate a pass. Candidate supported by Carbon source.
- **Additional model-backed reviewer:** independent S3* agent runs tests and reports, from OMC/Metis. Extra calls and prompts violate the minimal-resource preference.
- **General retry orchestration:** model/tool error retries from Hankweave/Zhi. Addresses transient failures but does not by itself establish correctness after dependency repair.

Architecture selection, exact protocol and acceptance conditions must be recorded **after** this comparison is published. The final small harness is not required to claim an autonomous S3* VSM function. A narrow deterministic source-derived verification primitive may be used without importing Carbon's full runtime.
